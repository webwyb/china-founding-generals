# 公示、反馈与图片使用核验

## 当前公示信息

`config/compliance.json` 统一配置主办者、备案和公开联系邮箱。2026-11-17从腾讯云ICP备案管理页核对主办者为吴延彬，`binnwu.top` 对应 `京ICP备19002969号-2`；用户再次确认该号，并指定 `beijingwyb@163.com` 用于公开反馈。未保存腾讯云账户截图、证件或其他私密信息。

公安备案公共查询遇到人机验证，未取得本网站真实编号及核验链接。用户要求“查询不到，就先用已有的数据”；因此 `policeNumber`、`policeUrl` 同时留空，页面不显示虚构编号。今后核实后同时补入这两项，使用公安机关提供的官方核验链接。不能把公安备案平台自身页脚的编号用作本站编号。

所有页面页脚展示ICP备案号并链接工信部备案查询；`/about/#site-info` 同时展示主办者。`/about/#copyright`、`#correction` 与 `#ai-landscapes` 分别提供版权、勘误和AI景观说明，静态HTML也可使用。

## 反馈方式

说明页公开邮箱并提供两类邮件草稿，人物页的入口自动附人物姓名及正式档案地址。访客需要通过自己的邮件工具确认发送；网站不自动发送或上传附件。来信材料用于核验、回复和处理反馈，运营者收到后仍需实际核对出处／权利依据，并更正或停止使用有问题的内容。入口可用不代表邮件送达和处理流程已实测。

## AI景观显式标识

首页家乡景观、人物页景观及图片替代文字明确标注AI来源；纪念卡页面解释其为地域文化意象，不是历史实景照片，不用来证明人物经历。家乡山河卡片的同一Canvas成图内写入“背景景观由AI生成”，预览、保存弹层和下载保持同图。素笺及地域待核实的构图不添加不适用的景观标签。

本轮未改动历史肖像或景观原件，未对人物进行AI生成、补脸或重绘。已完成的是可见提示和输出卡片内的显式标识；原始景观文件的隐式标识、生成服务条款及相应标准的适用情况仍需专项核验，不宣称已完成全部AI标识合规。

## 图片授权待核实清单

运行 `npm run audit:images` 从实际文件及来源清单生成：

- [可检索清单](../data/compliance/image-rights-review.html)：按姓名、ID、域名、核验类别或图片类型筛选，每页50条；可离线打开，不加载来源站图片。
- [结构化记录](../data/compliance/image-rights-review.json)：每项包含本地路径、SHA-256、来源／原始文件链接、原许可记录、优先级和待核实事项。

当前共1638张：1609张历史肖像（含8张精选肖像）、29张AI景观；5位缺图人物单列。全数为待核验记录，没有新标记为已取得授权。类别如下：

| 核验类别 | 数量 |
| --- | ---: |
| 来源记录明确提到书面授权要求，未见凭证（张耀祠） | 1 |
| 未明确开放许可／使用范围待核实 | 1534 |
| 许可信息不足，需追溯原文件（含8张精选肖像） | 37 |
| 已有Public domain标记，适用依据待复核 | 36 |
| 已有CC0标记，原文件许可待复核 | 1 |
| AI景观生成条款与标识待复核 | 29 |

身份核验、公开可见、来源机构或现有许可标签均不自动构成授权证明。逐图确认权利人、授权凭证或其他合法使用依据，以及网站展示、COS分发、卡片合成、下载和分享范围；公版依据须结合具体作品和适用地区复核。生成器只整理原始记录，不作新的逐图法律结论。

补充权利凭证时应另行保留具体文件、权利人及适用范围，再更新生成流程；不要仅手动改生成JSON中的状态，下一次审计会重建清单。新增／更换人物照片或景观后重跑审计，`npm run validate:compliance` 会检查清单输入是否过期。完整 `npm run check` 已包含此项校验。
