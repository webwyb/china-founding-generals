# 微信小程序开发与验收

2026-11-17 起恢复微信小程序开发。首页、名录、人物、纪念卡与说明页共用 `src/pages/*/index.tsx`，不再保留 `.weapp.tsx` 页面分叉。Taro 仅在底层组件与服务使用平台文件，按目标编译为网页或原生小程序。主包包含轻量名录，完整生平、全文检索与原图从现有 HTTPS 服务按需获取，不把原图素材库复制进小程序。

## 已实现范围

- 首页：精选人物、家乡入口、全量名录入口。
- 名录：1614 个独立档案；姓名、别名、家乡及生平关键词；军衔与家乡组合筛选、联动计数；24 人分批、触底和按钮加载、重置与空态。
- 本地铭记：使用现有存储与 ID 清理逻辑；返回详情后刷新铭记状态。只保存在当前设备，与网页浏览器存储互不共享。
- 人物档案：完整等比肖像、原图预览、分段生平、背景说明、时间轴、来源展开与复制、资料差异、同乡人物。加载失败可以重试，不把精简名录冒充完整传记。
- 原生分享：首页、名录、人物和卡片页支持微信转发；人物与卡片分享均进入该人物的小程序档案。
- 纪念卡：家乡山河／素笺肖像；地域待核实自动使用素笺；复用 H5 `drawMemorialCard` 和二维码逻辑，以 Canvas 2D 导出 1200×1800 PNG。页面预览、图片查看和相册保存使用同一个临时文件，不重新排版。二维码打开公开网页档案，不是小程序码。
- 相册权限：仅用户点击保存时请求；拒绝、取消与其他失败均有明确说明，不自动打开设置或重复请求。
- 原生顶部导航避免胶囊遮挡；瓷白、松青、黛墨与朱砂；底部安全区；肖像使用 aspectFit，不裁切人脸。
- 说明页：资料口径、待核实说明、影像与 AI 景观说明、本地存储说明、勘误／版权反馈邮箱。

## 运行

```sh
npm ci
npm run check:weapp
npm run dev:weapp
```

使用微信开发者工具导入仓库根目录的 `project.config.json`，小程序目录为 `dist/weapp/`。已按用户提供的信息配置 AppID `wx2652a3141486dd4d`；联调、预览和发布需在开发者工具使用该小程序的授权开发者账号。AppSecret 不用于客户端，不应加入仓库。

`npm run build` 仍只输出 H5；`npm run check` 现在同时执行 H5 和微信构建及微信适配器／主包检查。`dist/` 不提交。

## 微信后台和服务配置

`config/weapp.json` 使用现有公开服务，不包含凭据：

- request 合法域名：`https://shanhe.binnwu.top`。
- downloadFile 合法域名：`https://media-1301987491.cos.ap-beijing.myqcloud.com`（肖像、景观、字体）。
- 保留合法域名、TLS 和证书校验；不以关闭校验作为验收条件。
- 在小程序后台按实际能力填写隐私保护指引，声明用户主动保存纪念卡时使用相册保存能力，并在真机核验首次授权、拒绝及再次保存。

字体使用仓库已有宋体子集对应的不可变 HTTPS 地址。字体请求需要素材服务允许微信页面来源的 CORS；现有网页的 CORS 白名单不代表已允许微信来源。字体加载失败或超时会回退系统宋体／系统字体，继续阅读与导出；Canvas 字体支持和字形实际效果需真机确认，不能保证与桌面浏览器逐像素相同。此处遵循 [Taro loadFontFace 文档](https://docs.taro.zone/docs/apis/ui/fonts/loadFontFace) 的平台约束。

## 数据与发布配套

编译时按现有 `scripts/data-version.cjs` 生成完整生平的版本路径；`personData.weapp.ts` 使用 `Taro.request`，校验 ID、姓名、传记、时间轴与来源结构，失败不缓存，支持重试。精简名录中的肖像统一替换回不可变 COS 地址，避免误用 H5 资源路径。保留 24 份完整档案的内存缓存，不将全文写入微信本地存储。

变更数据、精选图片或参与版本计算的共享文件后，必须先发布对应版本的 H5 人物 JSON 和素材，再发布小程序包；不可删除旧版小程序正在引用的资源。以下检查只读访问公开服务，可在发布前执行：

```sh
npm run validate:weapp:online
```

该检查核对精选与待核实地域人物、1614 人检索索引，以及精选肖像、字体、景观的 HTTPS 状态；不等于微信合法域名、授权或网络运行验收。普通 `check` 不依赖联网。

## 自动检查与待验收

`validate:weapp` 检查 1614／1609 人物与肖像计数、精简数据、HTTPS 肖像路径、人物请求去重及缓存、身份不符拒绝与重试、检索结构、导航栈处理、两种 Canvas 静态成图、同临时文件保存、权限／取消错误和构建包大小。对 API 使用明确的适配器，Canvas 使用 Skia；不是微信运行环境测试。构建检查将主包限制在 2 MiB 以内，并拒绝原图素材库或网页成图／监控代码进入包中。

已在微信开发者工具 2.02.2609250、基础库 3.18.0、iPhone 12/13 (Pro) 模拟器中检查共用首页、名录、元帅筛选与家乡人数联动、朱德完整档案和两种纪念卡生成。尚未执行 iOS／Android 微信真机或真实相册保存。仍待逐项验收：

1. 使用真实 AppID 和合法域名，核验原生分享与直接进入人物／卡片。
2. iOS／Android 微信完成首页→检索筛选→详情→铭记→返回原阅读位置。
3. 姓名较长、5 个缺图人物、190 位待核实人物、3 个地域待核实人物、原图失败与离线重试。
4. 两种卡片的中文字体、人物完整比例、AI 标识、二维码扫码及 1200×1800 实际文件。
5. 首次保存、拒绝、取消、设置开启后的重试、连续切换样式后的预览与保存一致性。
6. 小屏／大字模式、键盘、滚动恢复、长生平性能与微信客户端基础库兼容。

H5 已有浏览器验收范围仍见 `QA.md`；本轮不将其扩写成微信真机通过。

## 共用页面的维护边界（2026-11-17）

- 页面内容、筛选与铭记交互、人物卡片、阅读结构、纪念卡样式选择均在普通 `.tsx` 文件维护；`validate:weapp` 会拒绝重新引入五个页面的 `.weapp.tsx` 副本。
- `app.scss` 是两端的主要样式；`weapp.scss` 引用它，仅补原生图片尺寸、原生控件及语义元素的兼容。网页字体声明单独放在 `fonts.scss`；微信使用已有 `loadFontFace`，避免把字体打进主包。
- `Html.tsx` 直接导出网页原生语义标签，保留原有 h1、真实链接和 details；`Html.weapp.tsx` 映射为 Taro View/Text/Button 和可展开出处，不使用 WebView 套网页。
- 肖像、景观、图标和成图预览只在底层组件适配。`useCardImage` 统一返回生成状态、最终图片和错误；网页与原生 Canvas 均调用同一 `drawMemorialCard`。预览和保存复用同一个导出文件。
- 微信端先用 `downloadFile` 下载原图再交给 Canvas 解码。工具中的 `getImageInfo` 对 WebP 景观曾返回 invalid，改后山河卡已实际显示；没有改写或转绘历史照片，也没有关闭域名与证书校验。
- 已完成完整 `npm run check`（含两端构建）；最后图片下载兼容修正又通过类型检查、小程序构建、适配器检查与微信自带 `wcsc` 编译。最终主包 1,438,900 bytes（1.37 MiB）。H5 本轮没有新增浏览器实测；静态生成的 1614 份人物 HTML 和 SEO 校验通过。

共用代码不保证不同渲染引擎逐像素一致。网页复制／下载和微信转发／相册保存保留原生行为；真机字体、键盘、授权、完整阅读位置往返和全部页面尺寸仍按清单验收。
